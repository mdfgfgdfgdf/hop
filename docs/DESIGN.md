# HOP — Design language & UI rules

HOP is a modern, trustworthy Israeli mobility brand. Hebrew-first, RTL, mobile-first.
Think "liquid glass over a live map": blue and white, cool-white backgrounds, floating gray translucent
panels, one confident blue, big tap targets, very few steps to order a ride.

## Brand
| Token | Value | Use |
|---|---|---|
| `--brand` | `#2457FF` | primary actions, route line, accents, logo |
| `--ink` | `#111318` | text, dark surfaces, driver app background |
| `--paper` | `#F4F6FA` | cool-white page background (all three apps) |
| `--mist` | `#C7C9D1` | borders, disabled, secondary icons |
| `--success/--warning/--danger` | green / amber / red | status only |

Logo: `import { Logo, LogoMark } from "@/components/brand/Logo"` (static) or
`import { AnimatedLogo, AnimatedMark } from "@/components/brand/AnimatedLogo"` (living marks: the letters hop,
the needle in the logo acts as a gauge — `mode` idle | loading | moving | success, `hopOn`, `hopKey`).
Use the animated marks wherever state changes (top bars, searching, completion, auth submit). Never redraw the logo.
Tagline: **העיר שלך. הופ אחד.** · **MOVE WITH HOP**

Typography: Heebo (loaded in root layout). Display headings use the `display` class
(800 weight, tight tracking). Body 16px. Numbers use `tabular-nums` (`ltr-nums` class for
mixed LTR numerals inside RTL copy, e.g. plates, phone numbers, prices).

## Surfaces — real-product restraint
After owner feedback ("looks vibe-coded"), the system is deliberately plain, like a shipping ride-hailing app:

- Surfaces are solid white (`--surface`) with a 1 px hairline (`--line`) or one soft shadow. `.glass` is now
  a near-opaque white panel with a light blur. Keep blur for the few controls that float over the map.
- Buttons are flat and solid: `btn-primary` (HOP blue), `btn-ink` (near-black), `btn-glass` (white with a
  hairline), `btn-ghost`. No gradients, gloss, glow or shimmer. Radius is 14 px; pills are only for small chips.
- Radii: sheets 22 px (top corners), cards and inputs 10–14 px. Never round everything.
- Type: a tight scale (28/22/17/15/13), bold headings, tabular numbers for money and time, terse microcopy.
  No slogans in the UI, no exclamation marks, no explanatory paragraph under every control.
- Lists look like real app lists: 56–64 px rows, hairline dividers, trailing values.
- At most one discreet demo indicator per screen.
- Motion is quick (150–250 ms). Springs only for physical things (sheet, knob). The logo animates only while
  loading or searching.
- All three apps use the light theme. Always use token colours (`bg-bg`, `text-fg`, `text-fg-muted`,
  `bg-surface`, `border-line`).

## Components (`@/components/ui`)
`Button` (variants: primary · glass · ink · ghost · danger · success; sizes sm · md · lg · icon;
`loading`, `block`), `Glass`, `Sheet` (bottom sheet on mobile, side panel ≥ lg), `Field`/`Input`/
`Textarea`/`Select`, `Pill` (tones brand · ink · success · warning · danger · muted), `Spinner`,
`DemoBanner`, `EmptyState`, `Avatar`, `Stat`, `Segmented`, `Toggle`, `Skeleton`, `StarRating`,
`useToast()`. Icons: `lucide-react` (stroke 2, 18–22px). Motion: `motion/react` for sheet /
list / status transitions (spring, 300–450ms) — keep it subtle; respect reduced motion.

Map: `import { MapView } from "@/components/map"` (client-only). Props: `center`, `zoom`,
`markers` (`kind: pickup | dropoff | driver | me | poi`, `heading`), `polyline` ([lat,lng][]),
`fit` (points to fit), `fitPadding`, `onMoveEnd`, `onMoveStart`, `theme`. Children render on top
(use for the centre pin / overlays). It degrades to an offline flat canvas when tiles are
unavailable — the UI must still make sense without tiles.

## HOP Fluid — motion-first layer

The apps are built around one living map with glass floating over it. Shared pieces:

**Map (`@/components/map`, `MapView`)**
- Real vector tiles (OpenFreeMap positron) with brand-tinted water/parks and 3D buildings. When tiles fail or take more than 7 s, it switches to **HOP City** (`/map/hop-city.json`, generated by `scripts/gen-city.mjs`): a schematic 3D Gush Dan whose attribution reads "מפה סכמטית". Never present it as survey data.
- `pitch` / `bearing` animate the camera (home ≈ 40–50°, live ride ≈ 55°, receipts 0°). `ambient` slowly rotates idle hero maps.
- `polyline` draws itself in on a new destination and carries a travelling light. `routeStyle="guide"` gives a dashed straight hint.
- `driver` markers are top-view cars that glide between GPS updates and leave a fading trail. `nearby` markers are other available cars, fed by `GET /api/rides/nearby` (anonymous, ~10 m precision); never invent them.
- `radar` lays a sweeping radar flat on the ground while searching.
- Dev playground: `/lab/map?s=home|search|ride` (dev only).

**Primitives (`@/components/fluid`)**, gallery at `/lab/fluid` (dev only):
- `Island`: the status pill at the top of the map. Brand/glass/success/danger/ink tones, springs between compact and expanded, and crossfades its text, so the ride narrates itself in one place. `IslandEta` fills its trailing slot.
- `DragSheet`: a physical bottom sheet with snap points (≤ 1 = fraction of the viewport, otherwise px), flicks, rubber-banding and a keyboard-operable handle. On desktop it becomes a side panel. `onVisibleHeight` reports the visible height for map padding.
- `Morph`: screens merge instead of cutting. When `k` changes, the content dissolves into the next and the height springs.
- `RollingNumber`: odometer digits for prices, ETAs and earnings. Pass the formatted string (`formatILS`).
- `SwipeConfirm`: slide to confirm (RTL: right → left). It is also a real button, so click, Enter and Space confirm too. `requireSwipe` makes a click only nudge (for irreversible steps). Keyboard still confirms.
- `VehicleArt`: side-view cars per service type (`taxi`, `taxi_xl`, `premium`, `accessible`, `rideshare`). `moving` spins the wheels; `muted` is for unavailable services.
- `HopBurst`: a celebratory burst (driver found, ride completed).
- `LiquidLensDefs` + `.liquid-lens`: real refraction for small glass accents, Chromium only. Other browsers keep the frosted glass.

Motion rules: springs over durations; one hero motion per moment; every animation has a reduced-motion fallback (the global rule stops CSS animations; components check `useReducedMotion`).

## Layout rules
- Root is `<html lang="he" dir="rtl">`. Use logical properties (`ps-`, `pe-`, `ms-`, `me-`,
  `start`/`end`, `inset-inline-start`) — never `left/right` for RTL-sensitive layout.
  Arrows that mean "forward/continue" point **left** (`ArrowLeft`) in RTL.
- Mobile-first: design for 390×844, then tablet (768) and desktop (≥1024). On desktop the
  map pages keep the map full-bleed with the sheet as a side panel (`Sheet` does this).
- Primary action is always one big pill button at the bottom (52–60px tall), thumb-reachable,
  with `safe-bottom` padding. Secondary actions are glass/ghost.
- Accessibility: every interactive element has an accessible name; focus-visible rings are
  provided globally; status changes use `role="status"`/`aria-live`. Minimum tap target 44px.
- Loading: skeletons for content, `Button loading` for actions, never a blank screen.
- Errors: inline, in Hebrew, human (what happened + what to do). Use `useToast()` for
  transient confirmations.

## Honesty rules (product, not just design)
- Demo data is always labelled (`DemoBanner`, "תעריף הדגמה"). Never show demo numbers as real.
- Show the price **before** ordering; show the driver's net payout and HOP's commission separately.
- No guaranteed-earnings claims. Only server-computed amounts are displayed (`FareBreakdown`).
- Unapproved service types are shown as disabled with the reason, never hidden as "coming soon".

## Copy (Hebrew)
Short, warm, direct. Second person plural/neutral where possible ("בחרו יעד", "מחפשים נהג…").
Status labels come from `@/lib/labels` (`RIDE_STATUS_HE` etc.). Money via `formatILS` from
`@/lib/format` (agorot → ₪). Distances/durations via `formatDistance` / `formatDuration` / `formatEta`.
