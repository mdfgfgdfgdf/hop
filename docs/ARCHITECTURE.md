# HOP architecture

## Shape
One Next.js 16 (App Router, TypeScript) application serving three interfaces and the API:

```
src/
  app/
    (rider)/ride/**      rider app (light theme, map-first)
    (driver)/drive/**    driver app (dark theme)
    (admin)/admin/**     operator dashboard
    (auth)/login,signup  shared auth
    api/**               REST route handlers + SSE
  server/                domain + infrastructure (never imported by client code)
    db/        schema (Drizzle, Postgres dialect), client (PGlite | PostgreSQL), seed
    auth/      argon2 passwords, hashed session tokens, role guards
    pricing/   fare engine (pure) + tariff config
    geo/       providers: demo (offline) | osm (Photon + Nominatim + OSRM), traffic-aware routing
               (Google Routes / Mapbox driving-traffic / TomTom), traffic tile proxy, haversine, service areas
    dispatch/  ride state machine, matching, offers, cancellation, completion, serializers
    realtime/  in-process event bus → SSE
    driver/ support/ admin/  application services
    demo/      driver autopilot (demo mode only)
    audit/ security/ settings
  lib/                   client-safe: typed API client, DTO types, labels, formatters, SSE hook
  components/            ui primitives (liquid glass), map wrapper, brand, app shells
tests/                   vitest unit + integration (PGlite), playwright e2e
drizzle/                 SQL migrations
```

Boundaries: UI → `src/lib/api.ts` → route handlers → services → Drizzle. Route handlers only parse/validate
(zod) and authorize (`requireUser`/`requireRider`/`requireDriver`/`requireStaff`/`requireAdmin`); all rules live
in services so they are testable without HTTP.

## Database
PostgreSQL dialect everywhere. Development and tests use **PGlite** (Postgres compiled to WASM, file-backed
or in-memory) so `pnpm dev` works with zero setup; production uses a real PostgreSQL via `DATABASE_URL`.
Migrations are generated by drizzle-kit and applied on boot (`DB_AUTO_MIGRATE`) or via `pnpm db:migrate`.
Money is stored as integer agorot; percentages as basis points.

Key tables: `users`, `sessions`, `consents`, `driver_profiles`, `driver_documents`, `service_types`,
`pricing_configs` (versioned, one active), `promotions`, `service_areas`, `settings`, `quotes`, `rides`,
`ride_offers`, `ride_events` (timeline), `ride_track_points`, `ratings`, `ledger_entries`, `support_tickets`,
`ticket_messages`, `audit_logs`.

## Ride lifecycle
```
requested → searching → offered → accepted → driver_arriving → in_progress → completed
                 ↑          │          │              │
                 └──────────┴──────────┴──────────────┘  (decline / expiry / driver cancel → back to searching)
any non-terminal → cancelled (rider · driver-via-redispatch · system · admin)
```
Every transition runs in a transaction that locks the ride row (`SELECT … FOR UPDATE`), re-checks the current
status and uses conditional `UPDATE … WHERE status = <expected>`; the number of affected rows decides success.
Consequences: two drivers can never accept the same ride; a ride cannot be started or completed twice; stale
clients get a 409 (`offer_unavailable`, `invalid_transition`, `stale`).

### Quotes
`POST /api/quotes` validates the pickup is inside an active service area, fetches the route from the geo
provider, and computes one quote per enabled + legally approved service type with the active tariff. Quotes have
a TTL and are single-use; the ride is created *from the quote id* so the client never sends an amount.

### Matching
`runMatching(rideId)` ranks approved, online, non-busy drivers with a fresh location (≤ `driverStaleLocationSec`),
matching vehicle class, not excluded, within `searchRadiusM`, by ETA then distance (optionally by acceptance rate,
off by default for fairness). The best driver gets a single offer with a deadline (`offerTimeoutSec`). Decline or
expiry excludes the driver and re-runs matching; `maxOfferAttempts` / `searchTimeoutSec` end the search as
`cancelled (system, no_drivers_available)`. A background sweep (every 2.5 s, started by `instrumentation.ts`)
expires overdue offers and retries searching rides, so no ride is stranded if an in-flight request is lost.

### Money
Upfront pricing: the rider pays the quoted amount. On completion the engine writes three ledger rows:
`rider_charge`, `hop_commission`, `driver_payout` (`rider_charge = commission + payout`). Cancellation fees,
refunds and adjustments are additional rows. Reports aggregate the ledger; gross is never mixed with net.
Anomalies (actual distance/duration far from the estimate, very short rides, many offers, driver cancels) are
stored as `flags` on the ride for operator review.

## Realtime
An in-process `EventEmitter` bus publishes `ride.updated`, `ride.offer`, `driver.location`, … to per-user,
per-ride and admin channels. `GET /api/events` streams them as SSE with heartbeats; the client hook
`useRealtime` reconnects automatically, watches for stalls and tells the page to re-fetch authoritative state.
Clients also poll `GET /api/rides/active` as a fallback, so a dropped connection degrades to a few seconds of
latency rather than a stuck screen. Scaling out means replacing the bus with Redis pub/sub (one file).

## Security
- Argon2id password hashes; session tokens stored as SHA-256 hashes; httpOnly/SameSite cookies.
- Role checks in every handler; serializers strip counterpart phone numbers (masked), flags and admin notes
  for non-staff; riders only see their rides, drivers only rides offered to/assigned to them.
- zod validation on every body/query; in-memory rate limiting on auth, quotes, geocoding, uploads, locations.
- Document uploads: mime/size validation, stored outside the web root, streamed only to the owner or staff.
- Audit log for logins, verification decisions, suspensions, pricing changes, refunds, settings.
- Secrets only via environment variables; `.env*` is git-ignored.

## Legal gating
Service types carry `legalStatus`; only `approved` types can be enabled or quoted. Drivers must have every
required document approved before `verifyDriver(approve)` succeeds, and only approved drivers can go online or
receive offers. Service areas restrict where pickups are accepted.
